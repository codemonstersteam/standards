# Глоссарий и FAQ

Термины dev-standards в одном месте. Ссылки ведут к живым файлам репозитория.

## Термины

| Термин | Значение |
|---|---|
| **Харнес** | LLM-инструмент разработчика (dsh, opencode, pi, ZCode, Claude Code). Стандарты доставляются в каждый харнес через его точки интеграции: AGENTS.md, скиллы, хуки/плагины. |
| **Практика / стандарт** | Единица ядра: `box-spec`, `component-tests`, `modules`, `tbd`, `release`. Источник правды — [`rules/<id>/`](../rules/). |
| **Коробка** | Всё, что предоставляет API наружу: сервис, утилита, компонент. Проектируется со спецификации (см. `box-spec`). |
| **Контракт** | Машиночитанная спецификация коробки (`api-specification/openapi.yaml`, `asyncapi.yaml`, JSON Schema для CLI). |
| **`x-frozen:`** | Маркер в контракте — дата заморозки. Breaking замороженного контракта — STOP-условие: сначала вопрос оператору. |
| **Скилл** | `skills/<id>/SKILL.md` — model-часть практики («где и как»): грузится в контекст харнеса. Генерируется из `rules/`, править руками нельзя. |
| **Чекер (валидатор)** | `checks/check-<id>.mjs` — script-часть: детерминированная проверка. Контракт: `exit 0` + `OK — …` в stdout, `exit 1` + `✗`-строки в stderr; `--meta` — JSON-описание для генератора. |
| **Манифест** | `standards.json` — сгенерированный реестр практик для рантаймов: id, enforcement, скилл, чеки с `paths` (какие файлы триггерят проверку), `severity`, `trigger`. |
| **`rules/`** | Единственный источник правды: `meta.yaml` + `<id>/rule.yaml` (нормативы, STOP, checks-маппинг) + `<id>/prose/*.md` (Суть, Основание, языковая таблица). Артефакты (`skills/`, `standards.json`, футер AGENTS.md) генерируются `node tools/generate.mjs`. |
| **Эталон** | [AGENTS.md](../AGENTS.md) этого репозитория — краткая инструкция модели; `install.sh` доставляет его в проект как managed-блок. |
| **Managed-блок** | Фрагмент файла проекта между маркерами `<!-- dev-standards:start v1 -->` … `<!-- dev-standards:end v1 -->`. Принадлежит генератору: повторная установка заменяет блок целиком, не дублируя. |
| **Хук (PostToolUse)** | `hooks/standards-post-tool.mjs` — advisory-контроль в моменте: после правки файла запускает релевантные чекеры и возвращает модели `✗`-список через `additionalContext`. Никогда не блокирует. |
| **Мост** | `@deepseek-ai/dsh-hooks-claude-code` — пакет, через который dsh исполняет Claude-формат хуков (`.standards/hooks.json`). |
| **Fail-open** | Принцип хуков/плагинов: любая внутренняя ошибка — тихий `exit 0` без вывода. Стандарты не должны ронять инструмент разработчика. |
| **Enforcement: `model` / `script` / `hybrid`** | Как практика держится: только скилл-инструкция / только чекер / обе части. `release` — `model` (детерминированный расчёт тега — уровень CI). |
| **Severity: `warn` / `error`** | Вес нарушения в манифесте. `warn` — замечание (не роняет `--strict`), `error` — блок. По умолчанию нарушения — `warn`. |
| **`--report` / `--strict`** | Режимы `run-all.mjs`: report — всегда `exit 0`, печатает сводку (режим pre-commit по умолчанию); strict — `exit 1` на `error`. |
| **TBD / trunk** | Trunk-Based Development: один долгоживущий `main`, feature-ветки ≤ 2 дней, PR ≤ 600 строк, мержит человек. См. [tbd](../skills/tbd/SKILL.md). |
| **Greenfield-пропуск** | Легальность единственного bootstrap-коммита напрямую в trunk (1 коммит = репозиторий только создан). |
| **Вертикальный срез** | Единица декомпозиции: `internal/<slug>/` от входа до адаптеров, через всю систему, а не технический слой (`handlers/`, `services/`). |
| **1 вход / 1 выход** | Модуль принимает одну сущность `Request`, возвращает один `Result<Response, Error>`. |
| **ROP** | Railway Oriented Programming (Wlaschin): ошибки — значения по трубе, исключения через домен не летают. |
| **Valid-by-construction** | Доменный тип строится единственной фабрикой с проверкой; «голый» литерал вне фабрики запрещён — неверное состояние невыразимо. |
| **Head-pipe** | ASCII-труба data flow: `шаг -> Тип` + коды ошибок и маппинг на транспорт. Рисуется для человека и машины. |
| **Формула `N = 1 + Σ`** | Число компонентных сценариев на срез: happy path + различимые ветки адаптеров. Сценарий = Extension юзкейса. |
| **`@wip` / `@smoke`** | Теги сценариев: `@wip` — до фиксации (снимает фиксер, не автор), `@smoke` — обязательный минимальный прогон. |
| **SemVer** | Версия = совместимость контракта: ломает → `major`, добавляет способность → `minor`, чинит → `patch`. [semver.org](https://semver.org). |
| **Feature toggle** | Выключатель способности: новая функциональность едет в прод default OFF, включается отдельным прогоном (1% → 100%), служит рычагом отката. |
| **Provenance-штамп** | Комментарий-футер сгенерированного артефакта: `sha256:<8>` источника + версия. Дрейф ловит `generate.mjs --check`. |

## FAQ

**Чем хук отличается от pre-commit и CI?**
Скоростью и гарантией. Хук — мгновенная advisory-обратная связь модели в моменте правки; pre-commit — отчёт перед коммитом; CI — финальная гарантия. Это сотрудничество уровней, а не выбор одного: [иерархия контроля](combining-approaches.md).

**Что такое `x-frozen` и когда его можно снять?**
Дата заморозки контракта. Снять или изменить замороженное поведение — STOP-условие: остановись и спроси оператора; смена контракта идёт по схеме `box-spec` (сначала контракт, потом код).

**Мы трогаем легаси-файл — надо приводить весь проект к стандарту?**
Нет. Правила действуют на новый и изменяемый код: приведи к форме касаемый файл, отсутствующие артефакты проверки мягко пропускают, нарушения по умолчанию `warn`.

**Почему нарушения не блокируют работу модели?**
Ядро v0.5 — advisory: `✗`-список возвращается модели сразу после правки, и она исправляет в том же ходу. Блокирующий режим — `--pre-commit-strict` и CI. Финальная гарантия — не хук, а pre-commit-отчёт и CI.

**Куда вносить изменение стандарта?**
Только в [`rules/`](../rules/) (машинную логику — в `checks/`), затем `node tools/generate.mjs`. Ручная правка `skills/`, `standards.json` или футера AGENTS.md роняет `--check` — это защита от расползания копий.

**Как добавить новый чекер?**
Файл `checks/check-<id>.mjs` (zero-dep Node ≥18, контракт выше, `--meta`-JSON) + запись `checks:` в соответствующем `rule.yaml`. Несуществующий чекер в `rule.yaml` — ошибка генерации.

**Хук молчит после правки — он сломался?**
Скорее всего это штатный случай: путь файла не матчит ни один `paths` из манифеста (проверок для него нет) или нарушений нет. Проверь `standards.json` → `checks[].paths`. Инфраструктурная ошибка хука тоже выглядит как тишина — он fail-open.

**Как `release` гарантируется без чекера?**
Осознанно `model`-enforcement: классификация SemVer и дисциплина тогглов — решения человека+модели; детерминированный расчёт тега — уровень CI-рецепта проекта, не локальной петли.

**Почему скиллы ставятся симлинками, а не копируются?**
Обновление стандартов = `git pull` клон-репозитория; симлинк подхватывает новое без переустановки (у dsh скиллы ещё и hot-reload).
