# Комбинирование подходов: иерархия контроля

Где какой контроль применять. Ответ короткий: **везде сразу** — уровни не
конкурируют, а страхуют друг друга: моментный контроль обучает модель и ловит
нарушение до коммита, pre-commit даёт отчёт человеку, CI — финальную гарантию
команды.

## Пирамида

```
        ╱╲
       ╱  ╲
      ╱ CI ╲            ← абсолютная гарантия (мин)
     ╱──────╲
    ╱ pre-    ╲         ← высокая гарантия (сек)
   ╱  commit   ╲
  ╱──────────────╲
 ╱  контроль      ╲     ← мгновенная обратная связь (мс, advisory)
╱  в моменте (хук) ╲
```

| Уровень | Инструмент | Гарантия | Скорость | Что вешать |
|---|---|---|---|---|
| Контроль в моменте | хук/плагин/extension (PostToolUse, `tool.execute.before`, `tool_result`) | Advisory — модель видит `✗` и правит в том же ходу | мгновенно (~0.15 с, [замеры](hooks-guide.md#производительность)) | дешёвые статические чекеры; модельные подсказки (формула сценариев, правила TBD) |
| Pre-commit | `.git/hooks/pre-commit`: `generate.mjs --check` + `run-all.mjs --report` | Отчёт человеку (по умолчанию `exit 0`); `--strict` — блок на `error` | секунды | полный набор чекеров по манифесту + свежесть артефактов standards-репо |
| CI | `run-all.mjs --strict` (+ рецепты: `spectral`, `oasdiff`, прогоны тестов) | Блокирующая | минуты | обязательные командные проверки: контракт актуален, сценариев ровно N, TBD соблюдён |

Принцип распределения: **момент — для обучения и мягких правил; pre-commit —
для быстрых личных проверок; CI — для строгих обязательных**. Нарушение,
пойманное на нижнем уровне, дешевле: модель исправляет его сама, не тратя
человеческое ревью и цикл CI.

## Матрица «практика × уровень»

Кто что ловит (строки — практики ядра, `release` — guidance без чекера):

| Практика | Момент (хук) | Pre-commit | CI |
|---|---|---|---|
| **box-spec** | правка `api-specification/**` / `README.md` → `check-api-spec`, `check-docs`: `✗`-список в `additionalContext` | тот же набор, отчёт | `--strict`; перспективно: `spectral` (линт контракта), `oasdiff` (breaking-changes против прошлого релиза) — новыми чекерами |
| **component-tests** | правка `component-tests/**`, `docs/design/**` → `check-component-tests`: `@wip`, `@smoke`, дубли, `N = 1 + Σ` | тот же набор | `--strict` + полный прогон component-тестов (Docker Compose) |
| **modules** | правка `internal/**` → `check-modules`; `*.go` → `check-constructors` (только изменённые) | тот же набор | `--strict`; юниты фабрик по формуле `1 + Σ(ветки-предусловия)` |
| **tbd** | `git commit` → `check-tbd`: коммит в trunk, дифф > 600, ветка > 2 дней — до того, как коммит уйдёт | тот же набор, отчёт | `--strict` — единственный гарантийный уровень против долгоживущих веток |
| **release** | — (guidance: скилл подсказывает SemVer-вес и дисциплину тогглов) | — | ревью человеком; детерминированный расчёт тега — уровень CI-рецепта проекта |

## Как это сконфигурировано

- **Момент**: зоны путей и чекеры — в `standards.json` → `checks[].paths`
  (источник — `rules/<id>/rule.yaml`); событие и доставка — `install.sh`
  (хук dsh/ZCode/Claude, плагин opencode, extension pi). Детали —
  [hooks-guide](hooks-guide.md).
- **Pre-commit**: `./install.sh <проект> --pre-commit` (отчёт) или
  `--pre-commit-strict` (блок на `error`; для новых проектов и CI-проверки).
- **CI** (минимальный рецепт):

```yaml
# .github/workflows/standards.yml
- run: node tools/generate.mjs --check   # артефакты свежи (правки — только в rules/)
- run: node checks/run-all.mjs . --strict
```

## Прогрессивность

Уровни включаются по мере зрелости проекта: существующий код не требует
немедленной переделки — проверки мягко пропускают отсутствующие артефакты,
нарушения по умолчанию `warn`. `--strict` (error-блок) — цель, к которой проект
приходит постепенно, а не условие входа.
