# Стандарт: API-спека первична и заморожена

## Смысл

Контракт — источник истины. Изменение поведения начинается с правки
`api-specification/openapi.yaml`, затем реализация. Никогда наоборот.

## Hard rules (проверяет `check-api-spec`)

1. Файл `api-specification/openapi.yaml` существует.
2. Указана версия `openapi: 3.x`.
3. Секция `paths:` содержит хотя бы один путь; у операций описаны `responses:`.
4. Есть маркер заморозки `x-frozen: <дата>`. Breaking-изменения замороженного
   контракта запрещены; смена или снятие маркера — отдельный акт дизайна,
   а не кодинга.

## Как работать

- Новый endpoint → сначала опиши его в спеке (путь, методы, схемы, коды
  ответов), потом реализуй.
- Получил от валидатора замечание `✗ …` — исправь в том же ходу.
- Задача требует ломать контракт? Остановись и подними вопрос оператору
  (это смена контракта, не правка кода).
