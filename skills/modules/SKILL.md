# Стандарт: модули — 1 вход, 1 выход, корректность по построению

## Суть

Программа корректна потому, что постусловие каждого модуля удовлетворяет
предусловию следующего (композиция), — а не потому, что тесты прошли. Тесты
подтверждают формулу, не устанавливают корректность. Как программируем —
определяется проектированием модулей; поэтому data-flow рисуется для человека
и машины: это помогает машине уточнить упущенные требования.

## Hard rules

1. **1 вход, 1 выход.** Модуль (класс/функция/метод) принимает ровно одну
   сущность `Request` и возвращает один `Result<Response, Error>`. Флаги/опции —
   поля Request, не побочные входы; окружение привязывается заранее (готовый
   коллаборатор); настоящий join — именованный тип с конструктором. Общий
   `Context/State`, протянутый через трубу, запрещён.
2. **Вход по доменным диапазонам.** Допустимый диапазон каждого поля приходит
   из требований (словарь данных), не изобретается на дизайне. Инвариант = подтип,
   а не guard-функция.
3. **Valid by construction.** Доменный тип: приватное состояние + единственная
   фабрика `newT(raw) → Result<T, Error>`, проверяющая каждое поле по диапазону.
   «Голый» литерал доменного типа вне фабрики запрещён. Wire-DTO (`*Request/
   *Response`) без валидации — легальны только на краях; за краем существуют
   только валидные типы.
4. **Ошибки — значения (ROP).** Домен возвращает типизированную ошибку
   (`Result<T, Error>`), исключения через домен не летают. Упавший шаг коротко
   замыкает трубу, ошибка поднимается нетрансформированной и маппится на
   транспорт (HTTP-статус / exit code) ровно один раз — в ingress-адаптере.
5. **Чистое ядро, I/O-оболочка.** Бизнес-логика — чистые функции. Внешние
   эффекты — в автономных адаптерах (1 зависимость, 1 режим чтения/записи):
   адаптер — «пустая труба», единственное ветвление — маппинг кодов внешней
   системы в доменные ошибки. Голова среза держит адаптер, не raw-клиент
   (`*sql.DB`, `http.Client`). I/O и ingress не юнит-тестятся; юниты — фабрики
   и чистая логика по формуле `1 + Σ(ветки-предусловия)`, без моков.
6. **Вертикальный layout.** Срезу — свой корень (`internal/<slug>/` или
   эквивалент); технические слои (`handlers/`, `services/`, `io/`…) запрещены —
   они рвут вертикальную границу среза. Общее для ≥2 срезов — явный shared.
7. **Data flow рисуется.** Для каждого среза — head-pipe (ASCII-труба:
   `шаг -> Тип` + коды ошибок и маппинг на транспорт) в
   `docs/design/<slice>/module-tree.md`; та же труба человекочитаемо в README;
   дерево модулей — C3 Mermaid (зависимости внутрь). Все три вида совпадают
   узел-в-узел.

### Как выражается в языках

| | Go | TS/JS | Python | Rust |
|---|---|---|---|---|
| Фабрика | `NewX(raw) (X, error)`, поля unexported | `private`-поля + статическая фабрика / branded-типы | `__init__`-валидация / фабричная функция, `__setattr__`-заморозка | `TryFrom`/`new() -> Result`, непубличные поля |
| Result | пара `(T, error)`, без generic Result | юнион `Result<T,E>` / `Either` | возврат `Result`-подобного значения; исключения в домене запрещены | `Result<T, E>` нативно |
| Инвариант = подтип | непубличные поля + фабрика | branded/opaque-типы | `@dataclass(frozen=True)` + фабрика | newtype-обёртка |

## Существующий проект

Правила — на новые и изменяемые модули. Легаси-модуль не требует немедленной
переписки: при касании (правка бага/фичи) выводи его из зоны нарушения —
выдели фабрику, сверни исключения в значения, отдели I/O. Отсутствие
`internal/` или head-pipe — пропуск/замечание, не блок.

## Что проверяет скрипт

`check-modules` — в каждом `internal/<slug>/` ровно одна точка входа
(`index/handler/request/usecase`), `shared` — исключение; нет `internal/` — skip.
`check-constructors` (Go) — в изменённых `*.go`: доменные типы с фабрикой
без ветки ошибки, голые литералы доменных типов вне фабрики (warn).

## STOP

- задача требует второго входа в модуль или общего State через трубу — это
  граница нового среза, вопрос оператору;
- доменный диапазон поля неизвестен — вернись к требованиям, не изобретай.
