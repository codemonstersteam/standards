# Стандарт: модуль = один вход, один выход

## Правила

1. Модуль = срез: живёт в `internal/<slug>/`; общее — в `internal/shared/`.
2. **Один вход**: ровно один entry-файл в корне модуля
   (`index` | `handler` | `request` | `usecase`).
3. **Один выход**: один публичный результат (Response/результат use-case).
   Наружу модуль не экспортирует ничего, кроме него.
4. Межмодульное взаимодействие — через контракты, не через внутренности
   чужого модуля.

## Что проверяет скрипт (check-modules)

- в `internal/<slug>/` нет точки входа;
- точек входа больше одной.

«Один выход» и границы экспортов скриптом не ловятся — это ревью и дисциплина
модели (guidance). Нет `internal/` — проверка мягко пропускается.

## Как работать

- Новый срез → `internal/<slug>/` с одним entry-файлом, внутри — внутренности.
- Нужно что-то от чужого модуля → иди через его публичный результат или
  подними вопрос о контракте (STOP, если меняются границы).
