# Стандарт: коробка начинается со спецификации + Doc as Code

## Суть

Коробка — это всё, что предоставляет API: HTTP-сервис, CLI, очередь-консьюмер,
библиотека. Проектирование начинается со спецификации коробки, а не с кода:
контракт → документация → код. Никогда наоборот.

## Hard rules

1. **Контракт первичен и заморожен.** Машинный контракт (`api-specification/openapi.yaml`,
   `asyncapi.yaml` или JSON Schema для CLI) описан до реализации и помечен
   `x-frozen: <дата>`. Изменение поведения = сначала контракт, потом код.
   Breaking замороженного контракта — STOP, вопрос оператору.
2. **Ошибки исчерпывающи над юзкейсом.** Каждый видимый потребителю отказ —
   явный `error.code` в контракте: `#error responses (путь) == #Extensions юзкейса`.
   Маскировать отказ под успех запрещено.
3. **Один data-input на операцию.** Ровно одно тело запроса/сущность; два —
   значит, не хватает доменной схемы. Флаги/опции — поля этой сущности.
4. **Doc as Code.** Документация живёт в репо и выводится из замороженного
   контракта (`spec → docs → code`), не из исходников. У каждого артефакта
   ровно один дом: контракт — в `api-specification/`, как работает — pipe в
   README, дизайн среза — в `docs/design/<slice>/`, решения — в ADR.
5. **README коробки**: границы (Может / Не может), API-таблица из контракта,
   **pipe-описание** (как данные текут по шагам и где ломается — человекочитаемая
   копия head-pipe из скилла `modules`), таблица отказов со всеми `error.code`.

## Существующий проект

Правила действуют на новый и изменяемый код. Существующий README и контракт не
требуют немедленной переделки: при касании файла приводи его к форме; отсутствие
`x-frozen`/pipe — замечание (warn), не блок. Контракта нет и коробка не меняется —
проверки молчат.

## Что проверяет скрипт

`check-api-spec` — контракт существует, `openapi: 3.x`, `paths:`, `responses:`,
`x-frozen:`. `check-docs` — при существующем контракте: README существует,
содержит fenced pipe-блок и секцию таблицы отказов (warn).

## STOP

- нужно ломать замороженный контракт или снять `x-frozen` — это смена контракта,
  вопрос оператору;
- потребительский отказ не выражается кодом в контракте — расширяй спецификацию,
  а не изобретай код по ходу.
